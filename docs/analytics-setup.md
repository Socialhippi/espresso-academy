# Analytics setup

What the site sends, where it goes, and the exact steps to switch it on.

---

## What is already true

The site pushes typed events to `dataLayer` whether or not any container exists. `src/lib/analytics/events.ts`
is the whole vocabulary: a mis-typed event name is a build error, not a gap in a report nobody
notices for a month.

Nothing loads until two gates open:

1. **Consent.** Consent mode v2 defaults every storage type to `denied`, inline in the document
   head, before GTM can load. `src/lib/analytics/consent-mode.ts`.
2. **Idle or first interaction.** Even after consent, the container waits for the browser to be idle
   or for the first scroll or tap. GTM plus GA4 plus the pixel is roughly 120KB; on a 64%-mobile
   audience on Indian networks, letting that compete with the hero costs a real second of LCP.

India is not covered by the EU rules that make consent mode mandatory. Defaulting to denied anyway
is a choice: a student handing over a phone number and an email deserves the same treatment as a
reader in Berlin, and the banner is one tap.

## Importing the container

1. Open <https://tagmanager.google.com> and select the container.
2. **Admin → Import Container**.
3. Choose `docs/gtm-container.json`.
4. Workspace: **Existing** → `Default Workspace`, or a new one if you prefer to review first.
5. Import option: **Merge**, and **Overwrite conflicting tags, triggers and variables**.
   Merge rather than Overwrite-all, so anything the academy has added by hand survives.
6. Review the diff. You should see 21 tags, 19 triggers and 19 variables.
7. **Submit → Publish**.

### After importing, before publishing

Two things need a real value:

- **GA4 measurement ID.** The `GA4 - Configuration` tag is set to the value of
  `NEXT_PUBLIC_GA4_ID` at the time the file was generated. Confirm it matches the property you
  actually want.
- **The two Google Ads tags are paused, and they are meant to be.** They carry
  `AW-XXXXXXXXX` and `REPLACE_ME`. The academy has no Google Ads account yet; a conversion tag
  pointing at somebody else's ID is worse than no tag. When the account exists: put the conversion
  ID and label in, unpause, publish.

## What is deliberately not in the container

**The Meta Pixel.** It is loaded by the application, in `src/components/site/Analytics.tsx`.

The reason is deduplication. Every Meta event has an `event_id`, and the browser event and the
server-side Conversions API call have to send the *same* one or Meta counts the conversion twice.
That id is generated by this application from the booking or enquiry id. Routing the browser half
through a container would mean the academy could break the pairing by editing a tag, and would put
the two halves of one contract in two systems.

| Event | Browser | Server (CAPI) | Shared `event_id` |
|---|---|---|---|
| `Lead` | `generate_lead` on a successful enquiry | `/api/enquiry` after the Sanity write | `lead-<id>` |
| `Purchase` | `purchase` on the confirmation page | `/api/webhooks/razorpay` on capture | `purchase-<bookingId>` |

`purchase` fires once per booking per session, guarded by `sessionStorage`: the confirmation URL is
bookmarkable and every reload would otherwise report another sale.

## The events

Every one is pushed by `track()` and has a matching custom-event trigger in the container.

| Event | When | Key parameters |
|---|---|---|
| `page_view` | Every navigation, including client-side | `page_type`, `course_id`, `level` |
| `course_view` | A course page | `course_id`, `level` |
| `course_filter` | A filter chip on `/courses` or `/calendar` | `cta_id` |
| `batch_view` | A checkout page for one batch | `instance_id`, `course_id` |
| `cta_click` | Any `data-event` that is not a call, WhatsApp or map | `cta_id`, `location`, `course_id` |
| `whatsapp_click` | Any WhatsApp button | `location` |
| `phone_click` | Any `tel:` link | `location` |
| `map_click` | Any Google Maps link | `location` |
| `form_start` | First focus in a form | `form_id` |
| `form_error` | Client-side validation or a rejected submit | `form_id`, `reason` |
| `form_submit` | A submit that passed validation | `form_id`, `course_id` |
| `generate_lead` | A successful student or cafe enquiry | `course_id`, `event_id` |
| `waitlist_join` | A successful waitlist submit | `course_id` |
| `begin_checkout` | The checkout form mounts | `instance_id`, `value`, `currency` |
| `add_payment_info` | The Pay button is pressed | `instance_id`, `value` |
| `purchase` | The confirmation page, status paid, once per booking | `transaction_id`, `value`, `items`, `event_id` |
| `booking_failed` | Dismissed, declined, or an order that could not be created | `reason` |
| `guide_read` | The reader reaches the end of a guide | `guide_id` |
| `faq_expand` | An accordion question is opened | `cta_id` |
| `consent_update` | The banner is answered | `consent_analytics`, `consent_marketing` |

`data-event` attributes are read by one delegated listener (`src/components/site/ClickTracker.tsx`),
so adding a tracked button means adding an attribute, not an `onClick` and a client boundary.

## Meta Conversions API

Set these to switch the server half on:

```
NEXT_PUBLIC_META_PIXEL_ID=   # the browser pixel
META_CAPI_ACCESS_TOKEN=      # Events Manager → Settings → Conversions API → Generate access token
META_TEST_EVENT_CODE=        # while testing only
```

With `META_TEST_EVENT_CODE` set, events land in **Events Manager → Test Events** rather than in the
live dataset. Remove it before launch, or every real conversion is filed as a test.

Without `META_CAPI_ACCESS_TOKEN` the helper no-ops and logs `skipped`, and the enquiry and the
booking both complete normally. Email addresses and phone numbers are SHA-256 hashed before they
leave the process, which is Meta's requirement and also the right default.

## Verifying it

1. **Consent gate.** Open a page in a fresh profile with devtools on the Network tab. Nothing from
   `googletagmanager.com` or `connect.facebook.net` should load. Tap **That is fine**, then scroll.
   Both should load then, and not before.
2. **dataLayer.** In the console: `dataLayer.filter(e => e.event)`. You should see `page_view` and,
   after the banner, `consent_update`.
3. **GA4 DebugView.** Add `?gtm_debug=x` or use the GA4 debug extension, then walk a journey:
   course → enquire → thank-you should produce `page_view`, `course_view`, `cta_click`,
   `form_start`, `form_submit`, `generate_lead`.
4. **Meta.** Events Manager → Test Events with `META_TEST_EVENT_CODE` set. A single enquiry should
   appear once, not twice, with "Browser" and "Server" both listed against it. Twice means the
   `event_id` pairing is broken.

## Regenerating the container file

`docs/gtm-container.json` is generated, not hand-edited, so the trigger names cannot drift from the
event names in `src/lib/analytics/events.ts`. If you add an event, add it to that file and to the
generator, then re-import with **Merge + Overwrite conflicting**.
